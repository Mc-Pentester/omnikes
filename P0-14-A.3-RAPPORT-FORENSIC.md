## 7. roleRepository.canAccessStore()

**Fichier:** `src/repositories/role.repository.ts` (lignes 108-117)

```typescript
async canAccessStore(userId: string, storeId: string): Promise<boolean> {
  const authorizedStoreIds = await this.getAuthorizedStoreIds(userId);

  // null means global access to all stores
  if (authorizedStoreIds === null) {
    return true;
  }

  return authorizedStoreIds.includes(storeId);
}
```

**Méthode appelée:** `getAuthorizedStoreIds()` (lignes 88-103)

```typescript
async getAuthorizedStoreIds(userId: string): Promise<string[] | null> {
  const userRoles = await this.getUserRoles(userId);

  // If any role is global, user has access to all stores in organization
  if (userRoles.some((role) => role.isGlobal)) {
    return null; // null means global access
  }

  // Collect all store IDs from scoped roles
  const storeIds = userRoles
    .map((role) => role.storeId)
    .filter((storeId): storeId is string => storeId !== null);

  // Remove duplicates
  return [...new Set(storeIds)];
}
```

**Pseudo-code réel:**

```
canAccessStore(userId, storeId)
    ↓
getUserRoles(userId)
    ↓
si role.isGlobal === true
    ↓
retourner null (accès global)
    ↓
sinon
    ↓
collecter role.storeId des rôles scoped
    ↓
retourner liste des storeId
    ↓
si null → true (accès autorisé)
    ↓
si storeId dans la liste → true
    ↓
sinon → false
```

**Cas analysés:**

1. **Rôle global (isGlobal === true):**
   - Retourne `null` depuis `getAuthorizedStoreIds()`
   - `canAccessStore()` retourne `true` immédiatement
   - **AUCUNE VÉRIFICATION de l'organization du store**

2. **Rôle scoped (isGlobal === false):**
   - Collecte `storeId` depuis `role.storeId`
   - Vérifie si le `storeId` demandé est dans la liste
   - **AUCUNE VÉRIFICATION de l'organization du store**

3. **Store inexistant:**
   - La méthode ne vérifie pas si le store existe
   - Retourne `false` si le storeId n'est pas dans la liste

4. **Rôle inexistant:**
   - `getUserRoles()` retourne un tableau vide
   - `getAuthorizedStoreIds()` retourne un tableau vide
   - `canAccessStore()` retourne `false`

5. **Utilisateur sans rôle:**
   - `getUserRoles()` retourne un tableau vide
   - `getAuthorizedStoreIds()` retourne un tableau vide
   - `canAccessStore()` retourne `false`

## 12. Cross-Organization Risk

**Status:** CONFIRMED

**Severity:** CRITICAL

**Cause racine:**

1. **Modèle Prisma incomplet:**
   - `Role` n'a PAS `organizationId`
   - Impossible de rattacher un rôle global à une organization spécifique

2. **Implémentation `canAccessStore()`:**
   - `isGlobal === true` → retourne `null` → accès autorisé
   - AUCUNE vérification que le store demandé appartient à l'organization de l'utilisateur
   - Le commentaire dit "all stores in organization" mais le code ne vérifie PAS l'organization

3. **Absence de vérification cross-organization:**
   - `canAccessStore(userId, storeId)` ne reçoit PAS `organizationId`
   - Impossible de vérifier `store.organizationId === user.organizationId`

**Fichier:** `src/repositories/role.repository.ts`
**Lignes:** 88-117
**Fonction:** `getAuthorizedStoreIds()` et `canAccessStore()`

**Condition exacte:**

**Impact:**
- Un utilisateur avec rôle `isGlobal=true` peut accéder à **N'IMPORTE QUEL STORE** de **N'IMPORTE QUELLE ORGANIZATION**

### Option 1 — Correction modèle Prisma (recommandée)

**Ajouter `organizationId` au modèle Role:**

```prisma
model Role {
  id                String   @id @default(cuid())
  name              String
  description       String?
  organizationId    String?  // NOUVEAU: rattacher le rôle à une organization

  // Scope
  isGlobal          Boolean  @default(false)
  storeId           String?

  // Relations
  organization      Organization? @relation(fields: [organizationId], references: [id])
  userRoles         UserRole[]
  rolePermissions   RolePermission[]

  @@index([organizationId])
  @@index([storeId])
  @@map("roles")
}
```

**Modifier `getAuthorizedStoreIds()`:**

```typescript
async getAuthorizedStoreIds(userId: string): Promise<string[] | null> {
  const userRoles = await this.getUserRoles(userId);

  // If any role is global, get all stores in the user's organization
  if (userRoles.some((role) => role.isGlobal)) {
    // Récupérer l'organization de l'utilisateur
    const user = await prisma.user.findUnique({
      where: { id: userId },
      select: { organizationId: true },
    });

    if (!user) {
      return [];
    }

    // Récupérer tous les stores de cette organization
    const stores = await prisma.store.findMany({
      where: { organizationId: user.organizationId },
      select: { id: true },
    });

    return stores.map(s => s.id);
  }

  // Collect all store IDs from scoped roles
  const storeIds = userRoles
    .map((role) => role.storeId)
    .filter((storeId): storeId is string => storeId !== null);

  return [...new Set(storeIds)];
}
```

**Modifier `canAccessStore()`:**

```typescript
async canAccessStore(userId: string, storeId: string): Promise<boolean> {
  const authorizedStoreIds = await this.getAuthorizedStoreIds(userId);

  if (authorizedStoreIds === null) {
    // Fallback: vérifier explicitement l'organization
    const [user, store] = await Promise.all([
      prisma.user.findUnique({
        where: { id: userId },
        select: { organizationId: true },
      }),
      prisma.store.findUnique({
        where: { id: storeId },
        select: { organizationId: true },
      }),
    ]);

    return user?.organizationId === store?.organizationId;
  }

  return authorizedStoreIds.includes(storeId);
}
```

### Option 2 — Correction sans modification schéma (alternative)

**Modifier `canAccessStore()` pour vérifier l'organization:**

```typescript
async canAccessStore(userId: string, storeId: string): Promise<boolean> {
  const authorizedStoreIds = await this.getAuthorizedStoreIds(userId);
```

**Inconvénient:** Requiert 2 requêtes Prisma supplémentaires pour chaque vérification de store.

### Migration requise

Si Option 1 est choisie:
1. Ajouter `organizationId` à Role
2. Créer une migration pour:
   - Ajouter la colonne `organizationId` (nullable)
   - Backfill: pour chaque Role global, rattacher à l'organization des Users qui ont ce Role
   - Rendre `organizationId` non-nullable si tous les rôles sont rattachés

### Impact de la correction

- **Avant:** Un rôle global donne accès à TOUS les stores de TOUTES les organizations
- **Après:** Un rôle global donne accès à TOUS les stores de l'organization de l'utilisateur uniquement
- **Compatibilité:** Breaking change si Option 1 est choisie (nécessite migration)
- **Performance:** Option 2 ajoute 2 requêtes Prisma par vérification

### Recommandation

**Option 1** est recommandée car:
- Plus propre architecturalement
- Un rôle devrait logiquement appartenir à une organization
- Performance meilleure (une requête pour récupérer tous les stores de l'organization au lieu de 2 par vérification)
- Permet une meilleure traçabilité des rôles par organization
