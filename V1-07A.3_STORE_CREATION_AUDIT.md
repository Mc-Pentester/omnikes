```prisma
model Store {
  id                String   @id @default(cuid())
  organizationId    String
  name              String
  code              String   // Store code for identification
  address           String?
  city              String?
  country           String?
  phone             String?
  email             String?
  
  isActive          Boolean  @default(true)
  
  createdAt         DateTime @default(now())
  updatedAt         DateTime @updatedAt
  
  // Relations
  organization      Organization @relation(fields: [organizationId], references: [id], onDelete: Cascade)
  inventories       Inventory[]
  sales             Sale[]
  proformas         Proforma[]
  
  @@index([organizationId])
  @@index([code])
  @@map("stores")
}
```

## J. RISQUES

### Sécurité

**Risque 1 - OrganisationId depuis body**:
- ✅ **MITIGÉ**: `StoreService.create()` force `organizationId` depuis le paramètre, pas depuis le body
- ✅ **MITIGÉ**: L'API devra utiliser `requireCurrentOrganizationId()`

**Risque 2 - Absence de RBAC**:
- ⚠️ **ÉLEVÉ**: Aucune permission `store.create` n'est définie
- ⚠️ **ÉLEVÉ**: N'importe quel utilisateur authentifié pourrait créer un magasin si l'API est ajoutée sans RBAC

### Multi-tenant

**Risque 3 - Isolation organisation**:
- ✅ **MITIGÉ**: `StoreRepository.create()` utilise `organization: { connect: { id: organizationId } }`
- ✅ **MITIGÉ**: `StoreService.create()` force l'organisation depuis le paramètre

### Validation

**Risque 4 - Doublons de code**:
- ⚠️ **MOYEN**: Pas de vérification de doublon de code dans `StoreService.create()`
- ⚠️ **MOYEN**: Le schéma Prisma n'a pas de contrainte unique sur `code`
- ⚠️ **MOYEN**: Possible de créer plusieurs magasins avec le même code dans la même organisation

**Risque 5 - Validation des champs**:
- ✅ **MITIGÉ**: `storeSchema` Zod valide tous les champs obligatoires
- ✅ **MITIGÉ**: Email validé si fourni
