- Isolation: organizationId depuis session (body ignoré)

### 4. SÉCURITÉ MULTI-TENANT

**Détermination du tenant**:
- `organizationId` est **toujours** dérivé de la session via `requireCurrentOrganizationId(request)`
- Jamais utilisé depuis le body client pour déterminer le tenant
- Toutes les opérations vérifient l'appartenance à l'organisation

**Protection cross-tenant**:
- Repository: `updateMany` avec clause where sur organizationId
- Service: `belongsToOrganization` avant toute modification
- API: organizationId depuis session, body ignoré pour le tenant

**Validation**:
- PATCH: `storeSchema.partial().omit({ organizationId: true })` empêche modification du tenant
- Doublon code: vérifié uniquement dans l'organisation courante
