### 5. Cause exacte du 404

**CATÉGORIE: E** - Route existe mais logique interne retourne 404

Le 404 provient de la logique de vérification de la vente dans la route payments:

```typescript
// Ligne 78-81
const sale = await saleService.getById(id, organizationId);
if (sale.storeId) {
  await requireStoreAccess(request, sale.storeId);
}
```

Si `saleService.getById(id, organizationId)` ne trouve pas la vente avec l'organizationId, il retourne null, ce qui déclenche:

```typescript
// Ligne 119-123
if (error instanceof Error && error.message === 'Sale not found or access denied') {
  return NextResponse.json(
    { error: 'Sale not found or access denied' },
    { status: 404 }
  );
}
```

**Cause racine probable**: La vente créée par le POS n'appartient pas à l'organizationId de l'utilisateur authentifié, ou l'organizationId de la session est incorrect lors de l'appel payment.

**Raison**: Le 404 n'est pas un problème de code manquant ou incorrect. La route existe, les permissions sont correctement assignées, la logique RBAC est correcte. Le problème est un problème de données/état:
