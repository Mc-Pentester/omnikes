### C. DIAGNOSTIC DE LA BOUCLE POTENTIELLE

#### SCÉNARIO DE BOUCLE IDENTIFIÉ:

```
1. StoreContext useEffect (mount)
   → Charge { id: "xyz" } depuis localStorage (objet partiel)
   → currentStoreId = "xyz"
   → loading = false

2. /pos useEffect (mount)
   → user est présent
   → fetchStores() est appelé

3. fetchStores()
   → Dépend de currentStoreId = "xyz"
   → Fetch /api/stores
   → Valide si "xyz" existe dans fetchedStores

4. CAS A: "xyz" existe dans fetchedStores
   → setCurrentStore(fullStoreObject)  // ← MODIFIE StoreContext
   → currentStoreId reste "xyz"
   → Mais fetchStores est recréé parce que setCurrentStore/clearCurrentStore sont dans les dépendances
   → ⚠️ useEffect ligne 234 pourrait se re-déclencher

5. CAS B: "xyz" N'existe PAS dans fetchedStores
   → clearCurrentStore()  // ← MODIFIE StoreContext
   → currentStoreId = null
   → fetchStores est recréé
   → ⚠️ useEffect ligne 234 se re-déclenche

6. CAS C: fetchedStores.length === 1
   → setCurrentStore(fetchedStores[0])  // ← MODIFIE StoreContext
   → currentStoreId change
   → fetchStores est recréé
   → ⚠️ useEffect ligne 234 se re-déclenche
```

#### PROBLÈME FONDAMENTAL:

**`fetchStores` modifie le contexte sur lequel il dépend.**

```typescript
const fetchStores = useCallback(async () => {
  // ...
  setCurrentStore(store);  // ← Modifie le contexte
  // ou
  clearCurrentStore();    // ← Modifie le contexte
}, [user, currentStoreId, setCurrentStore, clearCurrentStore]);
//     ^^^^^^^^^^^^^^^^  ← Dépend de currentStoreId qui vient du contexte
```

Lorsque `setCurrentStore` ou `clearCurrentStore` sont appelés:
- `currentStoreId` change dans StoreContext
- `fetchStores` est recréé (nouvelle référence)
- Le `useEffect` ligne 234 se re-déclenche
- `fetchStores` est appelé à nouveau
- **BOUCLE POTENTIELLE**

### D. PREUVES

**1. Dépendances instables dans useEffect:**
- Ligne 234: `[user, fetchStores, fetchProducts, fetchTaxRate]`
- `fetchStores` est recréé à chaque changement de `currentStoreId`, `setCurrentStore`, ou `clearCurrentStore`

**2. Modification du contexte dans fetchStores:**
- Ligne 171: `clearCurrentStore()`
- Ligne 176: `setCurrentStore(store)`
- Ligne 181: `setCurrentStore(fetchedStores[0])`

**3. Objet partiel dans StoreContext:**
- Ligne 43: `setCurrentStoreState({ id: storedStoreId } as Store)`
- Crée un objet Store avec seulement `id`, tous les autres champs sont `undefined`

**4. Auto-sélection du magasin:**
- Ligne 179-182: Si un seul magasin, auto-sélection
- Cela modifie le contexte lors du premier fetch

### F. CORRECTION PROPOSÉE

**Option 1: Stabiliser les dépendances de fetchStores**

```typescript
// Dans /pos/page.tsx
const fetchStores = useCallback(async () => {
  if (!user) return;

  try {
    const response = await fetch('/api/stores?isActive=true');
    if (!response.ok) {
      throw new Error('Failed to fetch stores');
    }
    const data = await response.json();
    const fetchedStores = data.stores || [];
    setStores(fetchedStores);

    // Validation et restauration SANS modifier le contexte ici
    // Le contexte sera mis à jour par un useEffect séparé
  } catch (err) {
    console.error('Error fetching stores:', err);
    setError('Impossible de charger les magasins');
    setStores([]);
  }
}, [user]);  // ← Seulement user comme dépendance
```

Puis ajouter un useEffect séparé pour la validation:

```typescript
useEffect(() => {
  if (stores.length > 0 && currentStoreId) {
    const isValidStore = stores.some((s: Store) => s.id === currentStoreId);
    if (!isValidStore) {
      clearCurrentStore();
    } else {
      const store = stores.find((s: Store) => s.id === currentStoreId);
      if (store) {
        setCurrentStore(store);
      }
    }
  } else if (stores.length === 1 && !currentStoreId) {
    setCurrentStore(stores[0]);
  }
}, [stores, currentStoreId, setCurrentStore, clearCurrentStore]);
```

**Option 2: Charger l'objet complet dans StoreContext**

```typescript
// Dans StoreContext.tsx
// Au lieu de charger seulement l'ID, charger l'objet complet depuis une API
// Ou ne rien charger et laisser le composant décider
```

**Option 3: Utiliser useRef pour éviter la boucle**

```typescript
// Dans /pos/page.tsx
const isInitializedRef = useRef(false);

useEffect(() => {
  if (user && !isInitializedRef.current) {
    isInitializedRef.current = true;
    setTimeout(() => {
      fetchStores();
      fetchProducts();
      fetchTaxRate();
    }, 0);
  }
}, [user, fetchStores, fetchProducts, fetchTaxRate]);
```

**RECOMMANDATION: Option 1** - Séparer la logique de fetch de la logique de validation du contexte.
