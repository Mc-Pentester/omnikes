**Champs**:
- `id`: String @id @default(cuid())
- `organizationId`: String (relation vers Organization)
- `name`: String
- `code`: String (code d'identification du magasin)
- `address`: String?
- `city`: String?
- `country`: String?
- `phone`: String?
- `email`: String?

- `createdAt`: DateTime @default(now())
- `updatedAt`: DateTime @updatedAt

**Relations**:
- `organization`: Organization @relation(fields: [organizationId], references: [id], onDelete: Cascade)
- `inventories`: Inventory[]
- `sales`: Sale[]
- `proformas`: Proforma[]

**Index**:
- `@@index([organizationId])`
- `@@index([code])`

**Contraintes uniques**: Aucune (code peut être dupliqué entre organisations)

**État**: ✅ Le modèle est suffisant pour V1

### F. STORE CONTEXT

**Fichier**: `src/contexts/StoreContext.tsx`

**Stockage**: localStorage avec clé `omnikes.currentStoreId`

**Comportement**:
- ✅ Charge le storeId depuis localStorage au montage
- ✅ Persiste le storeId dans localStorage lors de la sélection
- ✅ Nettoie localStorage lors de la désélection
- ⚠️ Stocke uniquement l'ID, l'objet Store complet doit être validé par le composant

**Réactions**:
- ⚠️ Aucun magasin: Context ne gère pas explicitement ce cas (géré par POS)
- ⚠️ Magasin désactivé: Context ne filtre pas isActive (géré par API GET /api/stores?isActive=true)
- ⚠️ Changement d'organisation: Context ne valide pas automatiquement (POS refetch stores)

**Risques**:
- ⚠️ StoreId dans localStorage peut être invalide si l'organisation change
- ⚠️ Aucune validation automatique de l'appartenance organisation

**État**: ⚠️ Fonctionnel mais pourrait être amélioré pour la multi-tenance
