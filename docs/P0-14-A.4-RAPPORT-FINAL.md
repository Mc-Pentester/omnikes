## 2. Objectif

Fermer la frontière de sécurité User.organizationId → Store.organizationId pour empêcher un rôle isGlobal=true d'accéder à des stores d'autres organizations.

## 3. Cause racine P0-14-A.3

Dans `roleRepository.canAccessStore()`, la logique actuelle était:
```typescript
if (authorizedStoreIds === null) {
  return true; // PAS de vérification organization
}
```

Un rôle global retournait `null` depuis `getAuthorizedStoreIds()`, ce qui autorisait l'accès à TOUS les stores SANS vérifier qu'ils appartiennent à l'organization de l'utilisateur.

## 4. Correction appliquée

Fichier: src/repositories/role.repository.ts
Fonction: canAccessStore()
Lignes: 108-143

**Modifications:**
1. Ajout de 2 requêtes Prisma parallèles pour récupérer User.organizationId et Store.organizationId
2. Vérification d'existence: si user ou store n'existe pas → DENY
3. Vérification tenant boundary: si user.organizationId !== store.organizationId → DENY
4. Puis application de la logique RBAC existante (global/scoped)

## 5. Nouvelle frontière tenant

```
User.organizationId
        ↓
Store.organizationId
        ↓
MATCH → continuer RBAC
DIFFERENT → DENY
```

La vérification tenant est maintenant APPLIQUÉE AVANT toute autorisation RBAC.

## 6. Global role

**Avant:**
```
isGlobal → true → null → true (sans tenant check)
```

**Après:**
```
tenant check → user.org === store.org ?
    NON → DENY
    OUI → isGlobal → true → ALLOW uniquement dans la même organization
```

## 7. Scoped role

**Résultat:** Inchangé mais avec protection tenant supplémentaire
- Un rôle scoped ne peut plus accéder à un store d'une autre organization même si le storeId correspond
- La vérification tenant précède la vérification storeId
